# 后端开发手册 — 毕业生租房决策 Agent

> 本手册是《设计.md》(v0.2) 的**实现层分解**：按模块讲清楚每个文件"做什么功能、用什么技术、依赖哪些包、和谁交互、怎么验收"。
> 开发时按里程碑顺序（M1→M6）逐模块推进，每个模块独立可测。
> 项目根目录 = 本仓库根（对应设计 §7 的 `rent-agent/`），目录结构与设计文档一一对应。

## 0. 全局技术栈总览

| 层 | 技术 | 选型理由（面试可讲） |
|---|---|---|
| 语言/运行时 | Python 3.12 | 规避 3.14 生态兼容风险（LangGraph/Pydantic） |
| Web 框架 | FastAPI + Uvicorn | 对齐开发者主栈；异步；SSE 友好；展示 API 设计能力 |
| Agent 编排 | LangGraph (`StateGraph`) | 需要条件边（回溯）+ `interrupt()`（暂停等用户）+ checkpointer（会话恢复），线性 Chain 做不到 |
| 会话持久化 | `langgraph-checkpoint-sqlite`（SqliteSaver） | 零配置本地 `.db`；可切 MySQLSaver 秀 SQL |
| LLM | DeepSeek (`deepseek-chat`)，OpenAI 兼容协议经 `langchain-openai` 或 httpx 直调 | 成本 ≤0.15 元/次；JSON mode |
| 地图 | 高德 Web 服务 API（geocode + 路径规划），httpx 调用 | 通勤必须真实计算，不能模型估 |
| 结构化存储 | SQLAlchemy Core（无 ORM）+ SQLite/MySQL 双模 | 表结构共用 DDL，`DATABASE_URL` 一键切换 |
| 数据校验 | Pydantic v2 | LLM JSON 输出校验、API 请求/响应模型 |
| 测试 | pytest | 节点纯函数单测 + 端到端 + interrupt 恢复 |
| 配置 | python-dotenv + `config.py` 集中 | 禁止魔法数字、禁止硬编码密钥 |

## 模块 1：配置中心 `app/config.py`

**对应需求**：设计 §7 环境变量约定；FR-03 速度表；§4 成本/延迟约束。

**功能**
- 集中所有魔法数字与开关，其余模块只允许从这里取值。
- 分组：LLM（key/base_url/model/超时）、地图（key/超时/告警阈值/速度表）、图执行（BACKTRACK_MAX=2、COARSE_TOPK=20、COMMUTE_LIMIT_MARGIN=1.3）、Mock 开关（MOCK_LLM/MOCK_MAP/MAP_FAIL_RATE）。
- 槽位默认值表（commute_mode 默认"公交"、max_walk 默认 15 等）也放这里。

**技术要点**
- 用 `pydantic_settings.BaseSettings` + `model_config = SettingsConfigDict(env_file=".env")`，字段带类型和默认值，环境变量自动映射（大小写不敏感）。
- 速度表 `COMPUTE_SPEED_KMH = {"驾车": 25, "公交": 18, "骑行": 15, "步行": 5}`，模块 5 的粗筛直接引用。
- 提供 `settings = get_settings()`（`lru_cache`），全项目单例。

**依赖**：`pydantic-settings`、`python-dotenv`。无外部 IO。

**验收**：`.env` 改一个值（如 MOCK_LLM=1），重启进程即生效；代码里 grep 不到散落的常量。

## 模块 2：存储层 `app/db.py`

**对应需求**：设计 §6.4 数据库选型；FR-03 缓存；§4 可观测（trace 落 DB）。

**功能**
- `get_engine()`：解析 `DATABASE_URL`，SQLite（默认 `sqlite:///./app/data/rent_agent.db`）与 MySQL 双模；SQLite 需开 `check_same_thread=False`（FastAPI 多线程访问）。
- 用 **SQLAlchemy Core** 定义 3 张表（不引 ORM）：
  | 表 | 列 | 说明 |
  |---|---|---|
  | `geocode_cache` | address(PK), lat, lng, created_at | 地理编码结果，进程级永久缓存 |
  | `commute_cache` | key(PK), minutes, source, created_at | key 格式见 FR-03：`{listing_id}|{lat:.4f},{lng:.4f}|{mode}` |
  | `trace` | id(PK auto), thread_id, node, ts, in_summary, out_summary, llm_calls, tokens, tool_calls | 每节点一条 |
- `init_db()`：启动时 `create_all`（Core 的 `MetaData.create_all`，SQLite/MySQL 共用 DDL）。
- 提供薄函数：`cache_get_row(table, key)` / `cache_put_row(table, key, ...)` / `insert_trace(row)`，供 tools 与节点调用。

**技术要点**
- 表结构集中一个 `metadata = MetaData()`；MySQL 切换只改 `DATABASE_URL`，列类型用 `String(255)`/`Float`/`Integer`/`Text` 等两端兼容类型。
- 时间戳统一 UTC ISO 字符串存 `String(32)`，避免 SQLite 无原生 DATETIME 的坑。
- LangGraph 的 checkpoint 表由 SqliteSaver 自管（`checkpoints.db` 单独文件），**不与业务表混用**，避免用户误清业务数据时把会话也清了。

**依赖**：`sqlalchemy`；（可选）`pymysql`。

**验收**：单测对 SQLite 建表→插缓存→读缓存→再跑 `init_db()` 幂等。

## 模块 3：房源数据与生成 `scripts/generate_listings.py` + `app/data/listings.json`

**对应需求**：设计 §6.1；FR-02 筛选。

**功能**
- 按 §6.1 价格公式生成 200 条北京模拟房源：`BASE[district] × ROOM_COEF[room_type] × DIST_SUBWAY_COEF[walk桶] × ORIENTATION_COEF × FLOOR_COEF ± N(0, 5%)`，系数表原样落在脚本顶部常量（可配置、可复现——固定 `random.seed`）。
- 20–30 个"小区"（海淀区西二旗/上地/中关村、朝阳望京/国贸/双井、昌平回龙观/天通苑…），每小区 5–10 条；`lat/lng` 在小区中心 ±0.01 度抖动；`walk_to_subway_min` 与经纬度按"步行 80m/min 到地铁站坐标"自洽。
- `listing_id` 格式 `BJ-{0001..0200}`；`title` 按 `{business_area}·{room_type 后缀}` 拼；`tags` 从字段派生（近地铁/朝南/有电梯）。
- 输出 `app/data/listings.json`（数组）。

**技术要点**
- 纯 Python + 标准库 `random`/`json` + `math`（距离换算），不引 pandas/numpy（依赖最小化）。
- 脚本可重复执行、结果确定性（seed 固定），方便评估标注复用同一份数据。
- 生成后自检：200 条、ID 唯一、价格分布落在 1500–6500、每条字段齐全——assert 后打印统计。

**依赖**：标准库。**这是 M1 第一步，先于一切图开发。**

**验收**：跑一次脚本产出 `listings.json`；抽 5 条人工核对价格公式与坐标自洽。

## 模块 4：工具层 `app/tools/`（Agent 的"手"）

> 统一约定（设计 §7 代码规范）：**所有外部调用必须经过 tools/，节点内不直接发请求**；每个函数纯函数风格，异常就地转降级值，不向上抛裸异常。

### 4.1 `tools/listings.py` — `search_listings`

**功能**：加载 `listings.json`（进程内缓存一次），按 `constraints` 做硬约束过滤：
- `price_monthly ≤ budget_max`
- `room_type` **前缀匹配**（"合租" 匹配 `合租-*` 三档；"整租" 匹配 `整租-*`；"不限" 全过）
- `walk_to_subway_min ≤ max_walk_to_subway_min`（字段存在时）

**技术**：普通 Python 过滤，无包依赖。软约束（朝向/tags）**不在这过滤**，留给排序与报告。返回 `list[dict]`，按价格升序稳定排序（保证可复现）。

**验收**：对应 FR-02——结果 100% 满足硬约束；空结果返回 `[]` 而非报错（空判定交给上游条件边）。

### 4.2 `tools/map.py` — `geocode` / `commute_time` / `haversine` / 缓存

**功能**（FR-03、§5.5）：
- `haversine(a, b) -> km`：直线距离，纯计算。
- `geocode(address) -> {lat, lng} | None`：先查 `geocode_cache` 表；miss 才调高德 `/v3/geocode/geo`；失败返回 `None`（上游走"提示重输"降级）。
- `commute_time(listing_id, dest_coord, mode) -> {minutes, source}`：
  1. 组装缓存 key `{listing_id}|{lat:.4f},{lng:.4f}|{mode}` 查 `commute_cache`，命中直接返回；
  2. miss → 高德 `/v3/direction/transit/integrated`（公交/步行/骑行）或 `/v3/direction/driving`（驾车），超时 `MAP_TIMEOUT_MS`；
  3. 成功 → `source=api` 写缓存；失败/超时 → `haversine × 速度表` 估算，`source=estimate` 也写缓存（避免重试风暴）；
  4. 全局计数器 `MAP_CALL_COUNT` 累加，超过 `MAP_CALL_WARN_THRESHOLD=50` 打 warning 日志。
- `MOCK_MAP=1` 或 `MAP_FAIL_RATE>0` 时委托 `tools/mock.py`（见 4.4）。

**技术**：`httpx.Client(timeout=...)` 同步调用（节点是同步函数，图执行在线程池里跑，避免 async 传染全图——面试可讲这个取舍）；mode→高德 transit 策略映射表放本模块。

**验收**（§9.1 test_tools）：已知坐标对 Haversine 误差 <1%；mock 断言缓存命中不发请求；`MAP_FAIL_RATE=1.0` 全走 `source=estimate`。

### 4.3 `tools/llm.py` — 统一 LLM 封装

**功能**（§5.6、§5.8）：
- `llm_call(messages, schema=None) -> str | dict`：
  - POST `{LLM_BASE_URL}/chat/completions`（httpx 直调 DeepSeek 兼容接口；**不引 langchain-openai**，减少一层黑盒，token 统计自己掌控）；
  - `schema` 非空时加 `response_format={"type":"json_object"}`，并用 Pydantic 模型校验输出，**失败重试 1 次**（把报错拼进追问）；仍失败抛 `LLMJsonError`，由各调用点走"规则兜底"（如 L1 正则抽取）；
  - 每次调用累加 `LLM_CALL_COUNT` / `LLM_TOKEN_COUNT`（进程内计数器 + trace 记录），供 §4 成本约束核对；
  - `MOCK_LLM=1` 时委托 `tools/mock.py`。
- `load_prompt(name, **vars) -> str`：读 `app/prompts/{name}.md`，`str.format_map` 填 `{var}`，附带版本号常量 `PROMPT_VERSION` 写入 trace。

**技术要点**：
- Prompt 文件即代码：启动时全部读入 dict 缓存；改 prompt 不改调用点。
- JSON mode 输出解析要容错：剥掉 ```json 围栏再 `json.loads`。

**验收**：干净输入解析出完整槽位 JSON；喂脏输出时校验重试路径可触发；`llm_calls` 计数与 trace 一致。

### 4.4 `tools/mock.py` — 离线 mock

**功能**（设计 §7 Mock 注入）：
- `mock_llm_call(messages, schema=None)`：按消息内容里的标记路由到固定返回（如 prompt 里含 `[[TASK:parse_input]]` 就返回 `MOCK_SLOT_JSON`），让单测完全确定化。
- `mock_geocode / mock_commute_time`：返回固定坐标 / `距离÷速度` 纯估算；`MAP_FAIL_RATE` 概率抛超时。

**技术**：字典路由，零网络。脏输入跑批用 `MOCK_LLM=1 MOCK_MAP=1 MAP_FAIL_RATE=1.0` 全离线。

**验收**：关掉网络跑 `pytest` 全绿。

## 模块 5：Agent 状态图 `app/graph/`（项目灵魂）

### 5.1 `graph/state.py` — AgentState

**功能**：原样落设计 §5.3 的 `TypedDict`（messages、user_profile、missing_slots、constraints、dest_coord、listings_pool、candidates、commute_results、backtrack_count、tried_constraint_sets、negotiation_*、final_recommendations、validation_failures、status、llm_calls、trace）。

**技术要点**：
- `trace` 字段需要"每节点 append 而非覆盖"→ 用 `Annotated[list[dict], operator.add]` reducer；其余字段默认 last-write-wins。
- messages 直接用 `langgraph.graph.message` 的 `add_messages` reducer。
- 附带一份 `initial_state() -> AgentState` 工厂函数，eval/测试复用。

### 5.2 `graph/nodes/` — 10 个节点

> 统一签名 `def node(state: AgentState) -> dict`（返回 state 增量，不原地改）；每个节点出口 `trace_append(node, in_summary, out_summary, ...)` 由公共小工具 `nodes/_trace.py` 提供。

| 文件 | 职责 | 关键逻辑 | LLM 点 | 对应 FR |
|---|---|---|---|---|
| `parse_input.py` | 最新用户消息 → 槽位 JSON | L1 调用（schema=Slots）；JSON 失败→正则兜底抽预算数字/地址；合并进 `user_profile`；重算 `missing_slots`（按必填优先级排序） | L1 | FR-01 |
| `clarify.py` | **interrupt 暂停问一个问题** | `interrupt({"type":"clarify","question":L2生成,"missing_slot":...})`；恢复后把回答写入 messages、更新 asked_slots；同一槽位最多问 1 次，超限用默认值并标记 `defaults_used` | L2 | FR-01 |
| `fetch_filter.py` | geocode + 硬约束筛选 | `dest_coord` 为空先 `geocode`（失败→status=failed 提示重输）；`search_listings(constraints)`；池空→交条件边转 backtrack | — | FR-02, FR-08 |
| `coarse_filter.py` | Haversine 粗筛 Top20 | 半径 `limit/speed×1000×1.3`；按 d 升序取 `COARSE_TOPK`；空→backtrack | — | FR-03 |
| `commute.py` | 精算通勤 | 对 Top20 逐个 `commute_time`（缓存命中不计 API）；结果写 `commute_results` | — | FR-03 |
| `evaluate.py` | 合格候选判定 | 过滤 `commute_min ≤ commute_limit_min` + 软约束排序（价格分位 0.4+通勤 0.4+地铁 0.2，与 §6.2 标注口径一致）；合格 <2 → backtrack | — | FR-04 触发条件 |
| `backtrack.py` | 自动回溯 ≤2 次 | 第 1 次半径×1.5，第 2 次通勤上限+10min；`tried_constraint_sets` 去重（约束 dict → `json.dumps(sort_keys=True)`）；超限→negotiate | — | FR-04 |
| `negotiate.py` | **interrupt 协商** | L3 生成 2–3 个放宽方案；`interrupt({"type":"negotiate","options":[...]})`；恢复后按选择改写 constraints、`backtrack_count=0` → 条件边回 fetch_and_filter；不生成推荐 | L3 | FR-04 |
| `report.py` | 生成报告 | L4 **一次批量**生成 Top K（≤5）理由+风险（数值只准来自字段）；规则触发风险提示；L5 摘要 | L4, L5 | FR-05 |
| `validate.py` | ID 白名单 | 每个 `listing_id ∈ listings_pool`；`commute_min ∈ commute_results[id]`（或 estimated 记录）；剔除不合格→`validation_failures`；剩余 <2 且重试 <1 → 回 report 重生成一次 | — | FR-06 |

### 5.3 `graph/build.py` — 图装配

**功能**：`StateGraph(AgentState)` 按设计 §5.2 状态图连边：

```
START → parse_input →(check_slots 路由函数)→ clarify | fetch_and_filter
fetch_and_filter →(池空?)→ backtrack | coarse_filter
coarse_filter →(Top20 空?)→ backtrack | commute
commute → evaluate →(合格≥2?)→ report | backtrack
backtrack →(未超限?)→ fetch_and_filter | negotiate
negotiate → validate_output          # 协商产出方案文本后直接出口
report → validate →(通过 or 重试用尽)→ END | report（重生成 1 次）
```

**技术要点**：
- 条件边路由函数是**纯函数**（输入 state 返回下一节点名/END），单测不启动图就能测路由逻辑——这是"有状态决策图"表述的落点。
- `compile(checkpointer=SqliteSaver(...))`；`interrupt()` 无需额外配置，恢复靠 `Command(resume=answer)`。
- 重试计数（report↔validate 循环）通过 state 里 `regen_count` 字段控制（补充字段，初始 0，上限 1）。

**依赖**：`langgraph`、`langgraph-checkpoint-sqlite`、`langchain-core`（消息类型）。

**验收**：`test_graph.py` 端到端 3 干净 + 5 脏输入；缺 commute_mode 必触发且只触发一次澄清；选完协商方案能续跑。

## 模块 6：Prompt 模板 `app/prompts/*.md`

**对应需求**：设计 §5.8。

**功能**：5 个文件，每个 LLM 调用点一份；占位符 `{var}`；每份头部第一行写 `<!-- version: v1 -->`，`load_prompt` 解析进 trace。

| 文件 | 要点 |
|---|---|
| `parse_input.md` | 系统角色 + 槽位 JSON schema 描述 + 3 个 few-shot（干净/缺 mode/含糊）+ "不确定输 null 不要猜" + 注入 `[[TASK:parse_input]]` 标记（mock 路由用） |

| `summary.md` | 报告摘要 ≤60 字 |

**验收**：人工读一遍无歧义；L1 对 5 条测试输入产出合法 JSON ≥4/5（LLM 抖动允许重试兜底）。

## 模块 7：API 层 `app/main.py`（FastAPI）

**对应需求**：设计 §5.7 FastAPI 协议。

**功能**

| 端点 | 行为 |
|---|---|
| `POST /chat` | 新会话：生成 `thread_id=uuid`，把 text 包成 HumanMessage invoke 图；返回 `{thread_id, type, content}` |
| `POST /chat/{thread_id}` | 续跑：`Command(resume=text)` 恢复被 interrupt 的图；返回同上 |
| `GET /trace/{thread_id}` | 从 trace 表按 ts 升序返回该会话完整 trace |
| `GET /health` | 存活 + DB 连通检查 |

**技术要点**
- **统一响应整形**：图执行结果可能是三种之一——`__interrupt__`（待用户回答）、report（done）、failed。封装 `format_result(graph_result) -> ChatResponse{type: clarify|negotiate|report|failed, content}`；interrupt 值从 `result["__interrupt__"][0].value` 取。
- 图节点是同步阻塞（httpx 调用），endpoint 用 `def`（FastAPI 自动丢线程池），**不写 async**——避免半异步半同步的混合体（面试点：为什么不用 async？答：调用量单用户，同步换确定性）。
- checkpointer 在 lifespan 里建（`SqliteSaver.from_conn_string("./app/data/checkpoints.db")`），业务表 `init_db()` 同处调用。
- 会话过期：`sessions` 元数据表记 `expires_at=now+7d`，`/chat` 入口检查（简化：lazy 删除，不引调度器）。
- CORS 打开给 `static/demo.html` 用。

**依赖**：`fastapi`、`uvicorn`、`langgraph`（Command）、`langgraph-checkpoint-sqlite`。

**验收**：curl 三段式走完（初始请求→澄清回答→report），中途 kill 进程重启后可从同 thread_id 恢复（checkpointer 持久化的直接证明）。

## 模块 8：评估体系 `eval/`

**对应需求**：FR-07、FR-08、设计 §6.2/§6.3、§9.2。

| 文件 | 功能 | 技术 |
|---|---|---|
| `profiles.json` | 10 组画像（先冻结标准再扩 20），schema 见 §6.2 | 由 `scripts/annotate_profiles.py` 半自动生成（脚本按"硬约束+综合排序前5"筛出 expected、6–10 名 acceptable），人工删改后冻结 |
| `dirty_inputs.json` | ≥5 条脏输入：缺 mode / 预算低于全池 / 地址不存在 / 地图超时（跑时置 MAP_FAIL_RATE=1）/ 只回"随便" | 每条含 `input`、`expect`（澄清/协商/failed 提示的类型断言） |
| `baseline.py` | 单次 LLM 基线：一条 prompt 塞 200 条房源+用户输入 → 直出 Top5 | 复用 `tools/llm.py`；解析失败按空推荐计（合规率惩罚进指标） |
| `metrics.py` | §FR-07 六项指标公式，纯函数（输入推荐结果+标注 → 输出指标 dict） | 候选命中率含 `acceptable_alternatives`；主指标=硬约束合规率 |
| `run_eval.py` | CLI：`--limit N`、`--baseline`；每画像独立一次性 thread_id 跑图（或基线），收集推荐→算指标→落 `results/{ts}.json` + 终端汇总表 | 通过 FastAPI 的 TestClient 或直接 invoke 编译图（选后者，少一层依赖）；脏输入组单独跑降级断言 |

**成本护栏**：跑批默认 `MOCK_LLM=1` 只验证流程；真实评估全量一次 ≤10 画像 × ≤8 调用 ≈ 数元以内（对齐 §4）。

**验收**：产出基线 vs Agent 对比表；硬约束合规率/命中率提升 ≥20pt；≥2 条失败案例分析写进 `results/` 旁的 `analysis.md`。

## 11. 开发顺序与依赖图（对齐里程碑）

```
M1: config → db → generate_listings → tools/listings → tools/map(+mock) → tools/llm → prompts → 直筒子 main 脚本(L1→筛选→精算→L4→打印)
M2: graph/state → nodes(逐个+单测) → build(先不含 backtrack/negotiate) → main.py /chat + SqliteSaver + clarify interrupt
M3: backtrack/negotiate 节点 + 条件边 + 协商续跑测试
M4: validate 节点 + trace 落 DB + /trace 端点 + 假 ID 注入测试
M5: annotate_profiles → metrics → baseline → run_eval
M6: demo.html → README → ADR → 录屏
```

**硬依赖**：`tools/` 先于 `graph/`；`graph/` 先于 `main.py` 的 interrupt 协议；`listings.json` 先于一切评估。

**踩坑预警**（设计 §10 的落地版）：
1. M2 第一件事跑通"单节点 interrupt + SqliteSaver 恢复"最小 demo，再动业务节点。
2. `interrupt()` 恢复时**节点从头重放**——interrupt 之前的代码必须幂等（不要在 interrupt 前写副作用到 DB；trace 写入放节点出口或走 reducer）。
3. SQLite + 多线程：连接 `check_same_thread=False`，写 trace 偶发 `database is locked` 时加 `timeout=30`。
4. 高德返回的 duration 单位是秒，写入缓存前统一转分钟。
