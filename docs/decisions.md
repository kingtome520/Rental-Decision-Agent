# ADR 决策记录

> 格式：背景 → 选项 → 决策 → 后果。对应设计文档 §11 交付物第 4 条。

## ADR-001 两阶段通勤计算（Haversine 粗筛 + 高德精算）

- **状态**：已定案（设计 §FR-03）
- **背景**：全量精算 200 条房源会打爆地图 API 配额且延迟不可接受；纯直线距离又不足以支撑"真实通勤"卖点。
- **选项**：A. 全量精算 B. 仅粗筛估算 C. 粗筛 Top20 + 精算 + 缓存 + 降级估算
- **决策**：C。冷启动单次 API ≤20，缓存命中二次查询 ≤5s，失败降级 `source=estimate` 并在报告标注。
- **后果**：需维护速度表与余量系数（config.py）；粗筛漏配风险由 1.3 系数覆盖。

## ADR-002 回溯上限 2 次 + 强制转协商

- **状态**：已定案（设计 §FR-04）
- **背景**：无解画像下自由回溯会死循环并放大 LLM 成本。
- **选项**：A. 不限回溯 B. 上限 2 后转协商（用户决策） C. 直接不回溯
- **决策**：B。`tried_constraint_sets` 去重，超限生成放宽方案交用户选择。
- **后果**：多一次 interrupt 交互；trace 中每次放宽有据可查（面试演示点）。

## ADR-003 ID 白名单防幻觉

- **状态**：已定案（设计 §FR-06）
- **背景**：LLM 生成推荐理由时可能虚构房源 ID / 数值。
- **决策**：报告中每个 listing_id 必须 ∈ 本次 listings_pool，commute_min 必须 ∈ commute_results；不通过即剔除并留痕，<2 条时重生成一次。
- **后果**：白名单通过率 100% 可验证；注入假 ID 必被拦截。

## ADR-004 模拟数据与决策层解耦

- **状态**：已定案（设计 §10 风险应对）
- **背景**：面试官质疑"数据是假的"。
- **决策**：房源仅经 `tools/listings.py` 的 `search_listings` 接口进入图内，替换为真实数据源不改任何节点逻辑。
- **后果**：README 需写明替换路径。

## ADR-005 FastAPI + LangGraph interrupt，而非 Streamlit / 自实现多轮

- **状态**：已定案（设计 §5.1、§5.7）
- **背景**：需要"图暂停等待用户回答后精确续跑"的会话机制。
- **选项**：A. Streamlit 会话状态 B. 自实现会话表 + 手动重放 C. FastAPI + LangGraph interrupt + SqliteSaver
- **决策**：C。checkpoint 持久化天然支持进程重启恢复，前端 curl 即可演示。
- **后果**：需吃透 interrupt 语义（节点重放幂等坑，见手册 §11 预警 2）。
